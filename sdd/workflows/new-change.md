# New change

1. Assign a stable change identifier.
2. Create proposal, requirements, design and tasks from `sdd/templates/`.
3. Resolve applicable Standards before accepting the design.
   Record available Story context in the proposal and apply the resolved Git Standard when creating the work branch; retain the stable SDD change identifier.
4. Obtain the review proportional to risk.
5. Mark implementation-ready only when blocking decisions are resolved.
